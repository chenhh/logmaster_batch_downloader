# Slint GUI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a native Slint desktop GUI for LogMaster batch audio downloading while modularizing the core network, parsing, and date handling logic.

**Architecture:** Separate calendar and network/parsing logic into `date_utils` and `client` modules in a library root (`src/lib.rs`). Slint UI runs on the main thread; long-running downloads and connection checks run asynchronously on Tokio background tasks communicating back to UI via `upgrade_in_event_loop` with `CancellationToken` support.

**Tech Stack:** Rust 2021, Slint 1.8 (`slint`, `slint-build`), Tokio, Reqwest (cookies enabled), `rfd` (native folder picker), `dirs` (standard OS paths), `thiserror`.

**Spec:** `docs/superpowers/specs/2026-09-30-slint-gui-design.md`

## Global Constraints

- Slint version floor is 1.8 (`slint = "1.8"`).
- Default Cargo feature is `gui`; `cli` remains available as an optional feature.
- All network operations must run on background Tokio tasks without blocking the Slint UI thread.
- Individual file download failures must be logged and counted without terminating the entire batch.
- Cross-platform target directory default uses `dirs::download_dir()`.

## Review Focus

1. **Server unreachable / timeout on login**: Connection test or download must catch network errors cleanly, display a red status indicator, and write error description to the log without panicking.
2. **Empty recording search results**: Query returns 0 records; UI must display informative message ("未搜尋到符合條件之錄音紀錄") and cleanly transition back to Idle state.
3. **Missing `Content-Disposition` header in download response**: Parser must fallback to `rec_{file_id}.mp3` and log a warning rather than aborting.
4. **Mid-download cancellation**: User clicks "停止下載"; background loop must exit on or before the current file completion, log cancellation, and restore UI to Idle state.
5. **Invalid characters in filename**: Remote server filenames with illegal characters (`/`, `\`, `:`, `*`, `?`, `"`, `<`, `>`, `|`) must be sanitized to prevent OS file write errors.

### Task 5: GUI Controller & Background Tokio Dispatch (`src/gui.rs`)

**Files:**
- Create: `src/gui.rs`
- Modify: `src/main.rs`
- Modify: `src/lib.rs`

**Interfaces:**
- Consumes: `LogMasterClient`, `date_utils`, `LogMasterUI`
- Produces:
  - `pub fn run() -> Result<(), Box<dyn std::error::Error>>`

- [ ] **Step 1: Implement `src/gui.rs`**

- Initialize `ui = LogMasterUI::new()?`.
- Set initial values (year/month ComboBox models, host, username, password, default download directory using `dirs::download_dir()`).
- Attach `browse-folder` callback: invoke `rfd::FileDialog::new().pick_folder()`, update `ui.set_output_path()`.
- Attach `test-connection` callback: spawn Tokio async task, call `client.login()`, update status text and color via `upgrade_in_event_loop`.
- Attach `start-download` callback:
  - Set `is-downloading = true`.
  - Create `Arc<AtomicBool>` or `CancellationToken` for cancellation.
  - Spawn Tokio task:
    1. Login to host.
    2. Search records for selected year and month.
    3. Iterate through records: check cancellation, call `client.download_record()`, log status, update progress bar.
    4. On completion or error: log final stats, set `is-downloading = false`.
- Attach `cancel-download` callback: trigger cancellation token, append log `"取消下載中..."`.
- Attach `clear-log` callback: set `ui.set_log_content("")`.
- Call `ui.run()?`.

- [ ] **Step 2: Update `src/main.rs`**

Dispatch to `gui::run()` when `feature = "gui"`, or CLI runner when `feature = "cli"`.

Run: `cargo check --features gui` and `cargo test`
